# 连续对话与可恢复状态

优先使用当前可见对话，不要求用户反复填写问卷。状态可以是简短的对话记录；只有长对话、续接或用户要求保存时才使用 [../assets/session-state.yaml](../assets/session-state.yaml)。持久化需要真实写入获准位置；不能声称跨聊天自动记忆。

## 最少要记住什么

- 当前版本的研究问题与用户目标，明确现实约束。
- 主张／假设的 ID、来源状态、支持与反对依据，待核实材料。
- 已问节点、用户真实回答的摘要、节点状态与判定理由。
- 每个决定性未知影响哪项主张，计划怎样取得信息。
- 本轮对问题、假设或设计的改动及用户是否确认。
- 当前论证状态、阶段结果、下一问及它的依据。

记录简短结论、引用和决定依据，不记录或要求私有的逐步内部思维过程。

## 来源状态

| 标签 | 含义 |
|---|---|
| 用户报告 | 用户提供的事实性陈述，未独立查看其原始依据 |
| 材料已核对 | 已实际查看的数据、文档或记录，带定位信息与核对范围 |
| 文献已核对 | 已实际查阅的外部来源，带真实出处 |
| 工作假设 | 为讨论暂时采用、尚未证实的前提 |
| AI 推断 | 从已有材料得到的解释性推断，附依据与边界 |
| 未知 | 现有材料无法确定 |

## 续接与变化

恢复时简述当前问题、最弱连接和上一轮未解决的节点；只在有实际分歧时要求用户更正。用户修正事实时更新其依赖的主张，必要时重开节点；不要让旧摘要压过新信息。

达到第三／第六轮检查点时，可用三句话概括“已解决／仍开放／现在建议”。默认不追加一大组独立问题。用户说“直接总结”时立即收束，不要求必须答完预定轮数。

示范问答不能进入“用户真实回答”；未执行的实验不能进入“材料已核对”；自行提出的重构不能进入“用户已确认目标”。记录存在这些区别比记录得很长更重要。
