# 从追问形成课题闭环

## 闭环不是论证自洽就算成功

先检查问题是否明确、概念是否可操作、结论是否与证据类型相称，再检查每条关键连接是否有证据或可执行的判别路径。一个尚未获得数据的完整方案可以达到设计准备状态；一个写得流畅但关键条件未知的方案仍然开放。

### 核心连接检查

| 连接 | 通过时能说清什么 | 未通过时保留什么 |
|---|---|---|
| 缺口 → 问题 | 为什么这项未知值得研究，缺口出处或待核实状态 | 价值／新颖性尚未建立 |
| 问题 → 解释／目标 | 正在比较、解释、预测、构建或证明什么 | 概念或研究类型未定 |
| 解释 → 预期证据 | 哪种证据会使主张更可信、减弱或未决 | 当前不可判别 |
| 证据 → 设计／分析 | 测量与设计能产生所需证据，主要假设与对照明确 | 识别／测量／分析缺口 |
| 设计 → 可执行 | 决定有效性的样本、数据、资源或前置条件可获得 | 可行性仍待确认 |
| 结果 → 结论 | 阳性、相反、混合、信息不足和质量失败不会被同一种解释吸收 | 事后解释／过强结论风险 |
| 结论 → 决策 | 知道何时继续、补证、收窄、转向或暂停 | 工作清单仍缺决策意义 |

“未适用”可用于不符合研究类型的栏目，但须说明对应证据标准；不能用它跳过核心主张的检验。无需为了形式完整发明实验、样本或统计分析。

## 状态与建议分开

`OPEN`、`DESIGN_READY`、`INCONCLUSIVE`、`SUPPORTED_WITHIN_SCOPE`、`REFRAME` 描述当前论证状态；“继续／补证／收窄／转向／暂停”是建议行动。设计准备不等于实验成功，结论局部受支持也不代表所有目标都达成。

给出状态时指向具体依据，尤其是决定状态的最弱连接。无法确认核心数据可得时不能给 `DESIGN_READY`；只有用户口述结果时注明“基于用户报告”，不能暗示已独立核验。

判断只针对目前范围，不给未经校准的“课题闭环分数”“发表概率”或科研价值总分。不因结果反对原假设就认定工作无贡献；也不因工作已经投入很多就保护原假设。

## 一份完成的阶段简报

默认用清楚的连贯文字和必要表格在对话中输出，按任务深度缩放：

1. **最终研究问题**：一句话，带对象、关键未知和必要边界；与初始想法的变化及理由。
2. **当前结果**：状态、限定结论、证据来源、最弱连接；没有数据时写设计判断而不是研究发现。
3. **解释地图**：主要假设／目标、最有力的竞争解释或尚未解决的分歧。
4. **证据与缺口**：什么已知、什么只是报告或假设、哪些需检索／取证；至少保留决定行动的未知。
5. **最小判别计划**：行动、为何能区分解释、必要条件、分析或解释标准；不堆技术。
6. **结果—决策矩阵**：对真正会改变决策的结果类别，说明可支持什么、不能支持什么和下一步。可使用 [../assets/decision-matrix.md](../assets/decision-matrix.md)。
7. **行动优先级**：现在先做的一项，之后有依赖关系的行动，以及停止／转向条件。具体时限只有用户给出资源与节奏时才承诺。
8. **课题逻辑叙事**：用一段约 150–300 中文字或等量篇幅组织“为什么研究、问什么、如何区分、结果如何改变认识、贡献在哪”。保留条件，不将计划写成已获结果。

提供能直接用于开题陈述的文字，但不声称已经完成正式开题报告、系统综述或完整实验协议。用户只要简短总结时可以合并栏目。

## 收束与重开

一个节点可标为 `resolved`（在当前范围内已解决）、`open`、`deferred`（有影响但暂时保留）或 `reopened`（新证据冲突）。指出重新打开的证据，不无故反复拷问已接受的回答。

达到检查点或用户要求结束时，交付阶段简报，不因没有完美答案就拒绝总结。若仍缺决定性信息，明确给出条件分支与一个最高优先级问题，不假称闭环已完成。
