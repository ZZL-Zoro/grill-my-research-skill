# 这个 skill 怎样把想法完善成科研推理工具

最初需求包括三件事：连环提问并回答、辩证判断、帮助组织课题。真正困难的是让它们
相互约束：追问必须由已有回答驱动，判断必须能被证据更新，组织出来的叙事必须保留
尚未解决的缺口。否则，一段流畅的模拟问答也可能把未经证实的前提包装成完整课题。

## 1. 从“问题很多”转向“问题能推进决策”

好的下一问来自上一答暴露的具体缺口。例如从“我准备做转录组”追问到“它要区分哪
两个解释”，比再问一次“你的研究意义是什么”更能判断下一步是否必要。

因此，每轮选一个主要缺口，优先考虑回答能否改变解释、设计或近期行动。回答不足时
帮助操作化；已经解决时承认解决。六轮是阶段交付的节奏设置，不是科学严谨性的阈值。

## 2. 从“正反都有道理”转向“按证据作裁决”

辩证性包含对主张的最强理解、相关反证与竞争解释、证据权重、以及判断更新条件。
它允许明确说“这个限定结论目前可以成立”，也允许明确说“当前证据反对它”。

双方承担相同的证据责任。一个无依据的反例设想不会自动推翻稳健观察；一个看似合理
的故事也不能越过实际支持范围。反馈的价值在于说明该保留什么、修改什么、如何知道
自己可能错，而非表态是否赞同。

## 3. 从“技术路线”转向“证据判别路径”

先明确想知道什么，再说明主要解释将在哪种证据上分叉，最后选择能产生这种证据的
方法。多个技术任务可以平行支持不同问题，也可能存在前置依赖；不能因为图画成箭头
就当作因果链已经成立。

对每个研究任务，要求能说清：它服务哪个问题、改变哪条主张、失败时其他任务是否仍
有价值。优先最早能改变决策的可行动作，而不是把所有可能实验放进计划。

## 4. 从“讲通预期结果”转向“结果能迫使更新”

如果预期结果支持假设、相反结果也被解释成支持同一个假设，计划没有足够判别力。
需要在合适的研究类型中定义何种反例、观察或失败条件会削弱主张。

除了支持与反对，还要容纳信息不足、质量失败与混合结果。每类结果连到结论边界和
下一步行动；无法解释的数据不能被强行叫作阴性证据。对没有数据的研究，输出的是
结果分支设计，而非虚构研究发现。

## 5. 从“写完算闭环”转向“两种闭合、保留开放点”

**设计层面的闭合**：研究问题、必要前提、判别证据、设计与分析、结果决策相互对应。
若关键数据或条件不可得，即使纸面逻辑完整，也尚不能称为可执行准备就绪。

**证据层面的支持**：实际可追溯证据支持一个有范围的结论，并记录仍未排除的解释。
它可能反对起始假设，也可能只回答原问题的一部分。

因此，`OPEN` 和 `INCONCLUSIVE` 是有用的阶段结果，不是需要用漂亮文字掩盖的失败。
停止或转向也可以是合理科研决策。这个工具不能保证得到阳性发现或发表结果。

## 6. 从“AI 自问自答”区分三种任务

| 用户真正要的任务 | 谁给事实性回答 | 助手的责任 |
|---|---|---|
| 交互拷问 | 真实用户与实际材料 | 等待回答、评估并追问 |
| 完整诊断 | 已提供的方案和证据 | 直接分析，缺失内容条件化，不冒充访谈 |
| 答辩演练 | 允许生成候选回答 | 标记模拟与假设，不能冒充用户已有实验 |

这一区分避免“连环问答”在形式上成立、在事实上全由模型虚构。用户随时可以要求
总结；阶段结果应能在当时真实掌握的信息下成立。

## 7. 从“一个通用模板”转向“共享逻辑、不同证据”

理论命题用定义、证明与反例来审查；质性研究关注材料选择、解释过程与反例；计算
研究关注任务、比较、数据独立性与外推。共享的是“主张凭什么成立，以及什么会改变
它”，不是所有项目都必须做随机实验或报告 p 值。

这些规则与状态是本项目的设计选择，尚未被验证为科研效果量表。少量具体方法来源
及其使用边界见 [方法背景](../references/methodological-notes.md)。后续改进应基于真实
交互中观察到的行为问题，而不是不断追加抽象口号。
